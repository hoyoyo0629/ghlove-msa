**전환 방법론이 두 갈래이고, 병존이 아니라 순서다: B안을 먼저 하다 벽에 부딪혀 중단 → A안 분석에 착수.** 이게 "세션마다 말이 다른" 진짜 원인이다(세션은 대화 공유 안 하고 메모리만 공유).

**타임라인(확인됨):** ghlove-msa 기능 상세구현 1·2차(2026-09-07·09-08) → **2026-09-15 10:02 커밋 `중단`**(사용자 설명: "미구현이 예상보다 많아 중단") → 같은 날부터 A안 분석문서 작성(04=09-15, 05=09-17). 즉 A안은 B안이 벽에 부딪힌 데 대한 재검토 산출물로 보는 게 자연스럽다. 단 "중단"이 "A안으로 확정 전환"을 뜻하진 않음 — 사용자는 아직 결정 못 한 상태(2026-09-17).

**A안 — AS-IS 저장소 in-place 스트랭글러 추출** (문서: `C:\Users\ghlove008\Desktop\고향사랑e음\1000.claude 분석 문서\`, 01~05단계, 2026-09-15~17)
- AS-IS `ghlove` 저장소 **안에** 모듈 추가(`gohyang-lib-contract`·`gohyang-starter-core`), opframework를 동일동작 `legacy`로 치환 → 인증주체·조회포트 3종(회원·지자체마스터·공통코드) 정비 → 서비스 순차 추출: **기반계층→답례품→기부→포인트→회원→주문→운영관리**.
- 충실도 안전망 우선(F0: 동작고정 테스트 + API 골든마스터 녹화 + 경계 래칫 CI). 송지훈 부장 매핑분석서·모듈설계·발주기관 요구(SEC-004 4역할, ARC/API/SEC/DEV/NFR)에 정렬. 결합 실측(S2: import 597·클래스연결 995·교차쓰기 32쌍)·테이블 소유 확정까지 되어 있음.
- 성격: 거버넌스 정렬·저위험·점진적. 단 SalesOn 잔재를 안고 가고, 서비스 하나 떼기 전 프레임워크 치환(F0~F5) 선행 필요.

**B안 — 클린 재구현 = 현재 `c:\workspace\ghlove-msa`**
- 별도 저장소, `com.ghlove.*`/Spring Boot 3/JPA로 처음부터 재작성하며 AS-IS 로직 포팅. 포팅 충실함은 확인됨(member 로그인 잠금조건이 AS-IS `AuthController.java:1200`과 동일, 코드에 라인주석까지). 규모 실구현(member 7,063·gift 7,661·point 2,853 LOC), `docs/inventory/*.tsv`에 항목별 판정.
- 성격: 클린 타깃·현대 스택 즉시. 단 **A안의 안전망(골든마스터·동등성 테스트)이 없어 손포팅 divergence 위험**, AS-IS와 병행 유지, A안 문서04의 경계·소유 결정을 아직 반영 안 함(예: `OP_USER_LOGIN_LOG`는 문서04에서 운영관리 소유인데 msa는 member가 기록 → 경계 불일치 가능성, 확인 필요).

**충실도·잔여량 실측 결과(2026-09-17, member/gift/point):** 인벤토리 판정 기준 잔여(재현누락+부분)는 member 26건(23%)·gift 3건(6%)·point 7건(20%)이나, 내용을 보면 gift는 사실상 완료, point 실질 사용자갭은 2건(탈퇴시 소멸·운영자수동적립), member 26건 중 9건은 SNS연계·전자서명(외부시스템 의존 보류건). **표본 라인대조 3건 모두 충실:** ① member 로그인 잠금이 AS-IS `AuthController.java:1200`과 동일, ② member 회원가입 구현분기 AS-IS 일치 + 인벤토리가 재현누락으로 찍은 `isAuth()`·`법정대리인(OP_USER_PARENT)`이 실제로 누락(=인벤토리가 정직), ③ point 원장(적립 rate·지자체별사용제한·만료 FIFO·멱등·취소시 미사용분만 회수)이 AS-IS보다 더 꼼꼼. **결론: "완료 67%"는 부풀림 아니라 신뢰가능하고, 중단은 (b)접근붕괴가 아니라 (a)잔여량+전방의존이다.** 단 point는 이벤트/SAGA로 재설계됨(=목표아키텍처, AS-IS 동기인라인과 다름) — 그 미결(ReadModel·예약)은 AS-IS 갭이 아니라 DA DB분리 설계에 게이트된 전방결정. **다음 세션은 "완료가 못 미더워 재구축"을 근거 없이 반복하지 말 것 — 실측상 member/gift/point는 B안 계속을 막을 근거가 없다.**

**이건 "이어가기 vs 재시작"이 아니라 방법론 선택이며, 코드 위 레벨(PM·발주기관·송부장)에서 결정할 사안이다.** 둘 다 DA DB분리 설계 확정에 게이트됨. 어느 쪽이든 **AS-IS 로직 + `docs/inventory` + ghlove-msa의 충실한 포팅은 재사용 가능한 입력**(A안이면 추출 참조자료, B안이면 계속 + 경계/안전망 보강).

**미해결(사용자 결정 대기):** 공식 전환전략이 A안(송부장 문서가 정본처럼 인용됨)인지, ghlove-msa(B안)가 승인된 병행/프로토타입인지 미확정. 근거 없이 한쪽으로 단정하지 말 것 — 2026-09-17 사용자가 세션 간 상반 조언에 불신 표함. 관련 [[scope-migration-not-greenfield]] [[as-is-logic-is-the-spec]] [[as-is-inventory-procedure]].
