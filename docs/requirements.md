# GHLOVE-MSA 기능 요구사항 정리 (RFP 기반)

> 원본: 사업 제안요청서(RFP) 기능 요구사항 SFR-001 ~ SFR-014
> 정리일: 2026-08-12
> 이 문서는 GHLOVE-MSA 프로젝트의 6개 서비스(회원/기부/포인트/답례품/주문/운영)를 구현할 때 항상 참조하는 기준 문서입니다.

## 서비스 매핑 요약

## 구현 원칙 (모든 서비스 공통, 절대 원칙)

- **하드코딩 금지**: 코드성 데이터(상태코드/카테고리코드/설정값 등)는 Java enum·상수로 박아넣지 않고 무조건 DB 테이블(공통코드 테이블 등)에서 조회하는 방식으로 관리한다.
- **이벤트 기반 통신 우선**: 서비스간 통신은 Kafka 이벤트 발행/구독이 원칙이며, 동기 REST 호출은 최소화한다.
- **SAGA 패턴**: 여러 서비스에 걸친 트랜잭션(주문-포인트-정산 등)은 SAGA(Choreography/Orchestration)로 처리하고 보상 트랜잭션을 정의한다.
- **CQRS ReadModel**: 각 서비스는 쓰기용 원장 DB와 별도로 조회 전용 ReadModel(DB/검색인덱스)을 두고, 이벤트로 동기화한다.
- **PK는 유지, FK는 서비스 경계를 넘지 않음**: DB per Service이므로 서비스 간 FK는 물리적으로 불가하며, 서비스 내부 FK도 일관성을 위해 사용하지 않는다. 서비스 경계를 넘는 데이터 정합성은 API/이벤트로 처리한다.

## 서비스별 요구사항 (SFR-002~007)

### SFR-002 — 회원·인증관리 서비스 전환 (담당: 회원 member)

- **통합 계정체계**: 일반회원, 재외국민, 지자체 담당자, 답례품 제공자, 시스템운영자 — 모든 사용자 유형을 하나의 계정 체계로 통합 관리
- RBAC(역할기반 접근제어) 적용, 지자체 담당자/답례품 제공자의 승인·해지, 권한 부여·회수 절차 표준화
- 로그인/인증: 금융인증서, 민간인증(카카오/네이버 등), 간편인증(AnyID) 등 외부 인증수단 연계
- 인증토큰/세션 관리(만료, 재인증 정책), 로그인/로그아웃, 비밀번호 변경, 아이디/비밀번호 찾기
- 계정 잠금(로그인 실패 횟수 초과), 휴면 전환/해제, 탈퇴 처리
- 다중 인증체계(MFA) 선택 적용
- 주요 행위 기록 감사 로그(로그인 성공/실패, 권한 변경, 계정 잠금/해제 등) — 표준 포맷으로 운영·보안 모니터링 연계 가능하게
- 데이터 파기 절차: 로그 데이터 분리 보관(익명화), 법적 보관 의무 데이터 별도 관리, 파기 이력 기록 및 보고

### SFR-003 — 기부관리(핵심 도메인) 서비스 전환 (담당: 기부 donation)

- 기부자 기부사업 선택: 거주지 외 지자체 선택, 기부사업 검색·선택·신청, 연간 기부한도 및 지자체별 세부 규칙 검증
- 기부금 납부 및 세외수입 연계: 지방세외수입시스템·위택스·서울시 세외수입 등과 연계(계좌이체/카드결제/간편결제)
- 기부 상태관리(신청/결제대기/납부완료/취소/환불 등), 기부 이력·통계 조회, 기부금 확인 기능
- 기부영수증 및 기부확인증 발급/재발급(전자 방식)
- 기부혜택(소득공제 등) 관리 및 발급 기능, 지자체별 기부혜택 관리
- 기탁서·오프라인 기부 등록, 지자체별 기부금 운용 현황 조회
- **★ 이벤트 기반 연계**: 기부 완료 이벤트를 포인트관리 서비스에 발행하여 기부포인트 적립을 트리거
- 주문·정산·통계 서비스와는 **이벤트 기반으로만** 연계되도록 설계 (동기 호출 금지)
- 기부금 납부 시 답례품 선택 기능 추가 등 기부 프로세스 통합 개선
- 기부 기능을 분석 후 성능 및 확장성을 고려한 MSA 분리

### SFR-004 — 기부포인트관리 서비스 전환 (담당: 포인트 point)

- 포인트 적립 규칙 및 원장 관리: **기부금액의 30%를 기준**으로 지자체별 적립 규칙 적용 (지자체마다 다름 — 하드코딩 금지, DB 관리 필수)
- 포인트 거래 원장과 회원별 잔액 테이블을 분리하여 관리
- 포인트 관리 기능: 적립, 차감(주문결제), 예약/예약해제, 소멸 처리, 오입금취소/반품에 따른 복원·조정
- 이벤트 기반 원장 갱신 및 트랜잭션 처리: 주문클레임 서비스 이벤트(주문확정/주문취소/반품완료 등)를 구독하여 원장 자동 갱신, SAGA 보상 트랜잭션으로 데이터 일관성 보장
- 포인트 조회 서비스: 거래내역·잔액 조회, 지자체별 사용현황, 만료 예정 포인트 안내를 **CQRS 기반 ReadModel**로 제공
- 데이터 전환 및 테이블 매핑 검증: 기존 포인트 관련 기능·통계·정산 입력 데이터 누락 없이 전환

### SFR-005 — 답례품관리 서비스 전환 (담당: 답례품 gift)

- 답례품 카탈로그 관리: 카테고리, 옵션, 규격/구성, 가격, 노출상태 등 — 지자체·제공자별 등록/수정/중지/폐지
- 지자체 정책 관리: 답례품 승인/반려, 노출기간 설정, 한시/상시 상품 설정, 기부금액 대비 선택 가능 기준 등 노출 정책
- 답례품 관리 및 주문 서비스 연계: 재고/판매수량 관리, 품절/판매중지 처리, 배송비·택배사 설정, 배송정책 — 주문관리 서비스와 이벤트 기반 연계
- 고객 후기/문의 관리(후기/문의/답변/신고), 운영관리 서비스의 통계·민원 분석용 데이터 제공
- 답례품 관리 화면 기능 API 재설계 — 조회/검색/필터링을 API 기반 구조로 재설계하여 성능·확장성 확보
- **대규모 트래픽(연말 성수기 12월) 대응**: 조회 전용 ReadModel 분리, 캐시·인덱스 최적화, 오토스케일링
- 비동기 이미지 처리: 썸네일 자동생성(소/중/대 3종), 웹 최적 이미지 표현
- 행안부 표준 카테고리 체계 적용(매핑, 메타데이터 강화, 추가/변경 용이한 확장 설계)
- 중복 등록 방지(등록 시 실시간 유사도 검사), 답례품 통합검색 기능 고도화(검색엔진 활용)

### SFR-006 — 주문·배송·클레임 관리 서비스 전환 (담당: 주문 order)

- 주문 생성 및 상태관리: 기부포인트 기반 주문 생성(장바구니, 결제, 주문상태 관리)
- 포인트 차감·복원 처리는 **SAGA 패턴** 적용하여 데이터 일관성 보장
- 배송관리: 송장번호 등록, 배송상태 추적, 배송완료 처리, 수취확인, 배송지 변경 — **택배사 시스템과의 연계는 운영관리 서비스가 담당** (역할 분리)
- 클레임 프로세스: 주문취소, 반품/교환 요청, 승인/거절, 회수/재발송, 포인트 복원, 재고 복원
- 이벤트 기반 비동기 연계: 주문·배송·클레임 각각 이벤트 발행 → 포인트관리·답례품관리·정산통계 서비스가 비동기로 후속처리
- 통계 및 SLA 관리를 위한 **ReadModel** 제공(제공자·지자체별 SLA 지표, 운영관리 대시보드에서 활용)
- 배송 자동화 및 구매확정 프로세스 개선(배송완료 자동처리, 구매확정 기간 단축, 클레임 처리 간소화)

### SFR-007 — 운영 관리 기능 서비스 전환 (담당: 운영 admin)

- 정산 프로세스 관리: 포인트 기준(지자체 담당자 정산내역 생성 → 제공자 세금계산서 발행 → 지자체 입금 → 정산 마감) — 주문·포인트 **이벤트**로 정산 데이터 생성·조정
- 운영 통계 및 분석 리포트: 기부·포인트·주문·답례품·회원 데이터 기반 운영통계, 민원 대응, 지자체별 실적 분석, 분담금 산정 리포트
- 운영 설정 및 관리자 기능: 공지사항·배너·팝업 관리, 지자체·제공자·운영자 권한 관리, **공통 코드·환경설정 관리** (하드코딩 금지 원칙의 실제 관리 지점)
- **외부 시스템 연계는 운영관리 서비스에서 일괄 관리**: 디지털원패스, 국민비서, 행정정보공동이용, 세외수입·전자영수증 등 — 이벤트·배치 기반 연계
- 운영 모니터링 기능: 배치 스케줄 관리, 알림·모니터링 설정, 장애 알림, 운영 로그 조회
- **지자체 전용 대시보드는 별도 애플리케이션으로 분리(경량화)**: 실시간 기부 현황, 답례품 재고, 배송 모니터링, 지역별 통계 시각화
- 멀티채널 알림: 기존 국민비서/알림 서비스 외 **카카오 알림톡** 추가 — 대량 발송 안정성·성능, 재시도 로직·발송 제한, 모니터링·통계

## 공통(플랫폼) 요구사항 — 전체 서비스에 적용 (SFR-001, 008~014)

### SFR-001 — 개발 공통 사항

- 응용프로그램 실행환경 자동구성 및 라이프사이클 관리, 이를 기반으로 관리
- CI/CD 도구로 개발/배포/운영 주기 단축 및 운영 중단 최소화
- **클라우드 최적화 MSA 구조**로 구축 (필수)
- 분산 아키텍처 트랜잭션 무결성: 연관 트랜잭션 중 하나가 실패하면 관련 트랜잭션은 **롤백**
- 서비스 오류 전파 방지: 호출 대상 서비스 오류로 기능이 막히지 않도록 대처 방안 마련
- ※ 적용 범위는 추진 상황에 따라 발주기관과 협의하여 조정 가능

### SFR-008 — 이벤트 버스 및 SAGA 트랜잭션 처리 기능 구현

- 도메인간 통신(기부/포인트/주문/답례품/정산/알림)은 **이벤트 발행·구독 기반**으로 구현, 동기 REST 호출 최소화
- 다중 서비스 트랜잭션(주문-포인트-정산, 포인트-정산, 주문-답례품 재고 등)은 **SAGA**(Choreography/Orchestration) 패턴으로 처리, 보상 트랜잭션 정의
- 이벤트 스키마 표준화(이벤트명/버전/payload 구조/상관ID), 이벤트 저장소(event store) 운영, 재처리 정책·절차 수립
- 다중 구독 및 확장성 고려 아키텍처(알림/통계적재/추천서비스 확장 등)

### SFR-009 — CQRS 기반 조회·검색(ReadModel) 서비스 구현

- 각 마이크로서비스의 원장(쓰기) DB와 독립된 조회용 DB(ReadModel)·검색 인덱스 구성, 이벤트 기반 동기화
- 대민/관리자/제공자 서비스 조회 기능(기부내역/포인트/주문배송/정산/통계 등)을 ReadModel로 통일된 방식 제공
- 통계·대시보드·보고서용 데이터마트 구성(트랜잭션 DB 부하 최소화)
- ReadModel 장애 대응(원장 복구·재동기화 절차), 데이터 정합성 확보를 위한 대사(SQL/쿼리 기반 검증) 규칙

### SFR-010 — API 게이트웨이 기능 구현 (Kong)

- 토큰 발급 및 인증, 엔드포인트별 API 호출 인증·인가, 접근정책, 특정 클라이언트 접근제어
- 공통기능(로깅/인증) 중복개발 방지, 요청·응답 표준화
- 다양한 API 라우팅, 과도한 트래픽 차단/해제(트래픽 제어), 고가용성 구성 및 오토스케일링
- 민간개방 API 기능(민간 이용업체 데이터 통합관리, 관련 통계)

### SFR-011 — 컨테이너 기반 오케스트레이션 및 서비스 메시 구현 (Kubernetes + Istio)

- 오케스트레이션: 컨테이너 배포·상태유지 스케줄링, 클러스터링, 오토스케일링/클러스터 스케일링
- 서비스 메시: 서비스 디스커버리, 라우팅·트래픽 제어, 로드밸런싱, 보안 통신, 트래픽 차단/해제
- 장애 발생 시 신속히 이전 버전으로 롤백하는 복구 기능

### SFR-012 — 클라우드 플랫폼 CI/CD 및 GitOps 기능 구현

- CI/CD: 자동/수동/스케줄러 트리거, 빌드 이미지 관리, 이미지 취약점 점검, 배포 이력관리·롤백, 파이프라인 가시성·리포트
- GitOps: 애플리케이션 소스 및 배포 스크립트 버전 관리
- 애플리케이션 품질 관리: 소스코드 품질점검 및 결과 제공

### SFR-013 — 풀스택 통합 모니터링, 로깅 및 추적 기능 구현

- 서비스 추적관리(분산 트레이싱), 로그 관리(수집·조회·다운로드·대시보드)
- 모니터링: VM/Kubernetes/스토리지/네트워크/DB/SW 전 리소스 메트릭 수집 및 대시보드
- 알람: 임계치 기반 자동알람(Trace/Log/Metric/에러), 다양한 채널(카카오 알림톡/Email 등) 및 웹훅

### SFR-014 — 구축 플랫폼 통합관리 기능 구현

- 점검/백업: 클러스터 자원·영구볼륨 백업/복원, 상태 대시보드, 취약점 점검, 리소스 효율화 가이드라인
- 통합관리 포털: 클러스터/리소스 정보·사용량, 네임스페이스별 워크로드, K8s 멀티클러스터 관리, 풀스택 통합 지원(SSO)
- 인증/인가 및 비밀번호 관리: 통합 로그인, 인증정보 중앙화, 데이터 송수신 암호화, 역할별 세부 권한
- 클러스터 리소스 변경 감사 로그 통합관리
- 마켓플레이스: 검증된 오픈소스·상용솔루션 컨테이너 기반 배포/관리
